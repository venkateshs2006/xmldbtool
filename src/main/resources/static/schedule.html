Spring Batch Pipeline Execution Steps Overview

Execution Sequence
1
Step 1: Automated Table & Schema Provisioning

Auto-creates or verifies required <entity>_flat staging tables and canonical relational destination tables in target database with bnpp_id UUID keys, delta versioning, and error tracking tables.

2
Step 2: Memory-Efficient StAX XML Streaming (Phase 1)

Spring Batch item reader streams 6GB+ XML records in chunks of 1,000 using constant O(1) heap memory. Tag values and attributes are extracted; nested structures are stored as raw XML strings. SHA-256 fingerprint delta detection skips unchanged payloads.

3
Step 3: Fault-Tolerant Checkpointing & Error Isolation (Never Abort)

Continuous progress checkpoints are saved to job_checkpoints. If any XML fragment has bad format or constraint violations, the error is isolated into migration_errors, while the job continues seamlessly to the next record.

4
Step 4: Dynamic Canonical Normalization (Phase 2)

Reads staged records from flat tables using Keyset pagination. Dynamically resolves master-child structures using ingestion.json (or XML discovery) and inserts into canonical destination tables with bnpp_id references. Flat record status is updated to NORMALIZED.

5
Step 5: Live Ingestion Telemetry & Monitoring Dashboard

Execution throughput (records/sec), JVM memory health, chunk write rates, and per-table breakdowns stream in real-time to the Monitoring & Telemetry dashboard.
